# 使用 Apitally 监控 Hono

应用能够返回响应并不代表它已经具备生产可用性。上线后还需要知道接口调用次数、响应时间、状态码和未处理异常。Apitally 提供 Hono 中间件，可以采集这些数据并发送到监控平台。

## 创建客户端

先在 [Apitally](https://apitally.io/) 中创建应用并取得 Client ID，然后安装 Node.js SDK：

```bash
npm install apitally
```

Client ID 应通过运行环境注入，不要直接写进源码或提交到 Git：

```text
APITALLY_CLIENT_ID=your-client-id
NODE_ENV=development
```

生产部署时使用平台的环境变量或 Secret 管理功能保存真实值。

## 注册中间件

在 `src/index.ts` 中导入 `useApitally`，并在业务路由之前注册：

```ts
import { useApitally } from 'apitally/hono'

const app = new Hono()
const apitallyClientId = process.env.APITALLY_CLIENT_ID

if (apitallyClientId) {
  useApitally(app, {
    clientId: apitallyClientId,
    env: process.env.NODE_ENV === 'production' ? 'prod' : 'dev',
  })
}

app.get('/health', (c) => c.json({ status: 'ok' }))
```

条件判断有两个作用：本地没有 Client ID 时应用仍能启动，TypeScript 也能够确认传给 SDK 的值一定是字符串。不要使用空字符串代替 Client ID，SDK 会将它识别为无效配置。

中间件应位于路由之前，否则前面已经注册的路由可能不会经过监控逻辑。`env` 用来区分开发、测试和生产数据，不要让不同环境共用同一个名称。

## 验证数据

启动服务后连续访问几次接口：

```bash
curl -i http://localhost:3000/health
curl -i http://localhost:3000/api/tasks
curl -i http://localhost:3000/not-found
```

等待 SDK 完成首次同步后，在 Apitally 控制台检查：

- 请求是否进入正确的环境。
- `2xx` 和 `4xx` 状态码是否被分别统计。
- 路由的请求量和响应时间是否出现。
- 服务端抛出异常时是否产生错误记录。

监控服务暂时不可用时不应影响 API 的正常响应，但仍要观察应用日志中的 SDK 配置或网络错误。

## 识别调用者

完成认证后，可以使用 `setConsumer` 把请求关联到内部用户或 API 客户端：

```ts
import { setConsumer } from 'apitally/hono'

app.use('/account/*', async (c, next) => {
  const user = await getAuthenticatedUser(c)

  if (user) {
    setConsumer(c, {
      identifier: user.id,
      name: user.displayName,
    })
  }

  await next()
})
```

`getAuthenticatedUser` 代表项目自己的认证逻辑，不是 Apitally 提供的函数。`identifier` 应使用稳定的内部 ID，不要使用密码、访问令牌或其他敏感信息。

## 日志和隐私

Apitally 还可以配置请求日志、请求体和响应体采集。启用这些功能之前，应先确认：

1. 登录凭据、Cookie、Authorization 请求头不会被记录。
2. 个人信息和业务敏感字段已经脱敏。
3. 日志保存期限符合项目的合规要求。
4. 大请求体和流式响应不会造成不必要的性能开销。

默认从请求数量、状态码、响应时间和服务端错误开始，通常已经能够回答大部分运行状态问题。

## 与 oRPC 一起使用

前一节通过 Hono 的 `/api/*` 中间件把请求交给 oRPC。Apitally 能够采集这条 Hono 路由的状态码和耗时，但不同 oRPC procedure 可能在控制台中聚合为 `/api/*`。

如果项目必须查看每个 procedure 的独立指标，应先检查实际控制台结果，再选择直接注册 Hono 路由、为 oRPC 增加独立 tracing，或使用能够识别内部 procedure 名称的监控方案。监控数据的路由粒度是验收项，不能只确认 SDK 已安装。

本节使用的是 Node.js Hono SDK。部署到 Cloudflare Workers 等 Serverless 运行时时，应按照 [Apitally Hono 指南](https://docs.apitally.io/setup-guides/hono)选择对应的 Serverless SDK。

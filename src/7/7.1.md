# Hono 框架

Hono 是一个基于 Web 标准的轻量级 Web 框架。路由处理器接收 Hono 的 `Context` 对象，再通过 `c.text()`、`c.json()` 等方法返回标准响应。

在 Node.js 中还需要 `@hono/node-server` 适配器。`app.fetch` 只负责处理请求，不会自己监听端口；适配器负责把 Node.js HTTP 请求交给 Hono。

## 创建项目

使用官方脚手架创建 Node.js 模板：

```bash
npm create hono@latest my-hono-app -- --template nodejs --install --pm npm
cd my-hono-app
npm run dev
```

打开 <http://localhost:3000>，页面会显示 `Hello Hono!`。

脚手架会安装以下核心依赖：

- `hono`：框架本身，负责路由、上下文和中间件。
- `@hono/node-server`：Node.js HTTP 服务器适配器。
- `tsx`：开发阶段直接运行 TypeScript。
- `typescript`：编译和类型检查。

## 启动服务

脚手架生成的 `src/index.ts` 结构如下：

```ts
import { serve } from '@hono/node-server'
import { Hono } from 'hono'

const app = new Hono()

app.get('/', (c) => {
  return c.text('Hello Hono!')
})

serve({
  fetch: app.fetch,
  port: 3000,
}, (info) => {
  console.log(`Server is running on http://localhost:${info.port}`)
})
```

这段代码包含三个关键步骤：

1. 创建一个 `Hono` 应用。
2. 注册 `GET /` 路由。
3. 使用 Node.js 适配器监听 3000 端口。

仅创建 `new Hono()` 或调用 `app.get()` 并不会启动服务器。

## 路由和响应

在 `serve()` 之前继续添加路由：

```ts
app.get('/health', (c) => {
  return c.json({ status: 'ok' })
})

app.get('/users/:id', (c) => {
  const id = c.req.param('id')
  return c.json({ id })
})

app.post('/tasks', async (c) => {
  const body = await c.req.json<{ title?: string }>()
  const title = body.title?.trim()

  if (!title) {
    return c.json({ message: 'title is required' }, 400)
  }

  return c.json({ id: 1, title, completed: false }, 201)
})
```

`c.req` 用来读取路径参数、查询参数、请求头和请求体，`c.json()` 的第二个参数是 HTTP 状态码。

可以使用 `curl` 检查路由：

```bash
curl -i http://localhost:3000/health
curl -i http://localhost:3000/users/42
curl -i -X POST http://localhost:3000/tasks \
  -H 'content-type: application/json' \
  --data '{"title":"Learn Hono"}'
```

## 中间件

中间件适合处理日志、跨域、认证和请求耗时等横切逻辑。Hono 中间件按注册顺序执行，`await next()` 前后的代码分别位于下游处理器执行之前和之后。

```ts
import { logger } from 'hono/logger'

app.use('*', logger())

app.use('*', async (c, next) => {
  const start = Date.now()
  await next()
  c.header('x-response-time', `${Date.now() - start}ms`)
})
```

中间件应在它需要覆盖的路由之前注册。认证中间件如果只保护 API，可以缩小匹配范围：

```ts
app.use('/api/*', async (c, next) => {
  const authorization = c.req.header('authorization')

  if (!authorization) {
    return c.json({ message: 'Unauthorized' }, 401)
  }

  await next()
})
```

## 404 和错误处理

统一响应格式可以让客户端更容易处理失败结果：

```ts
app.notFound((c) => {
  return c.json({ message: 'Not Found' }, 404)
})

app.onError((error, c) => {
  console.error(error)
  return c.json({ message: 'Internal Server Error' }, 500)
})
```

`notFound` 处理未匹配的路由，`onError` 处理路由或中间件抛出的异常。生产环境不要把堆栈和内部错误信息直接返回给客户端。

## 构建检查

官方 Node.js 模板提供 `build` 脚本：

```bash
npm run build
npm start
```

`npm run build` 使用 TypeScript 编译器检查类型并生成 `dist` 目录，`npm start` 运行编译后的 JavaScript。开发时继续使用 `npm run dev` 即可。

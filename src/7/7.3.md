# 使用 Cella 开发 Web 应用

[Cella](https://cellajs.com/) 是一个完整的 TypeScript Web 应用模板，不是一个安装后通过 `import` 使用的 Hono 插件。它为需要认证、权限、多租户、离线和实时协作能力的应用提供了较完整的工程结构。

## 先确认环境要求

Cella 当前仍处于预发布阶段，并且要求 Node.js 24。它不属于本章 Node.js 20 示例的连续步骤，应在独立目录和独立运行时中体验。

准备以下环境：

- Node.js 24。
- pnpm。
- Docker 和 Docker Compose。
- Git、GitHub CLI，以及可用的 SSH 配置。

创建项目前先检查版本：

```bash
node --version
pnpm --version
docker --version
git --version
gh --version
```

如果输出的 Node.js 版本仍是 20，应先使用版本管理工具切换到 Node.js 24。

## Cella 的组成

Cella 会生成一个由多个 workspace 组成的仓库，主要模块如下：

| 模块 | 作用 |
| --- | --- |
| `backend` | 使用 Hono、Zod 和 Drizzle 实现 API、数据库访问和业务逻辑 |
| `frontend` | 使用 React、TanStack Router 和 TanStack Query 构建客户端 |
| `shared` | 保存实体层级、权限、配置和跨端共享类型 |
| `sdk` | 根据 OpenAPI 文档生成客户端、类型和校验 schema |
| `cdc` | 从 PostgreSQL 变更中生成实时同步事件 |
| `yjs` | 提供可选的多人协作能力 |
| `infra` | 保存部署和基础设施配置 |

其中最值得关注的链路是：后端 Hono 路由和 Zod schema 生成 OpenAPI 文档，`sdk` 再生成前端调用代码。这样前后端共享的是接口契约，而不是直接共享数据库模型。

## 创建和运行项目

使用官方创建工具生成自己的项目：

```bash
pnpm create @cellajs/cella my-app
cd my-app
pnpm install
pnpm generate
pnpm docker
pnpm seed
pnpm dev
```

这些命令分别完成以下工作：

1. `pnpm generate` 生成数据库迁移、OpenAPI 文档和 SDK。
2. `pnpm docker` 启动 PostgreSQL 等本地服务。
3. `pnpm seed` 写入本地演示数据和初始用户。
4. `pnpm dev` 并行启动后端和前端开发服务。

项目生成后，端口、环境变量和初始管理员等信息以创建工具的输出及项目内 `.env` 文件为准，不要把真实密钥提交到 Git。

## 推荐的阅读顺序

面对一个完整模板，不需要从第一行源码开始阅读。可以沿着一次 API 请求逐层查看：

1. 在 `backend` 中找到 Hono 路由和对应的 Zod schema。
2. 查看 Drizzle schema、迁移和数据库查询如何实现业务逻辑。
3. 运行 `pnpm generate`，观察 OpenAPI 文档和 `sdk` 的变化。
4. 在 `frontend` 中找到使用 SDK 和 TanStack Query 的页面。
5. 最后阅读权限、多租户、CDC、离线缓存和部署模块。

修改数据库结构或 API 契约后，运行：

```bash
pnpm generate
pnpm check
pnpm test
```

`pnpm check` 会重新生成 SDK、执行类型检查并检查代码风格。生成文件发生变化时，应当把源 schema 和生成结果一起审阅。

## 什么时候使用 Cella

Cella 适合希望直接采用其技术栈，并且确实需要多租户、离线或实时同步能力的应用。对于只有少量接口的服务，直接使用 Hono 和数据库库通常更简单。

由于 Cella 仍处于预发布阶段，命令和目录可能继续变化。实践时应同时参考 [Cella Quickstart](https://github.com/cellajs/cella/blob/main/cella/QUICKSTART.md) 和 [Cella 仓库](https://github.com/cellajs/cella)，不要依赖旧截图或非官方安装方式。

# 使用 oRPC + Scalar 开发 API

普通 Hono 路由可以直接处理 JSON，但随着接口增多，请求校验、响应类型和 API 文档容易出现偏差。oRPC 可以用同一份 TypeScript 定义完成输入校验、输出校验、路由实现和 OpenAPI 描述，Scalar 再把 OpenAPI 文档渲染成交互式页面。

本节继续使用上一节创建的 `my-hono-app`。

## 安装依赖

下面的版本已经在 Node.js 20 中验证：

```bash
npm install @orpc/server@1.14.13 @orpc/openapi@1.14.13 \
  @orpc/zod@1.14.13 zod@4
```

示例使用 oRPC 自带的 OpenAPI Reference 插件。插件通过 CDN 加载 Scalar 页面，因此不需要安装当前要求更高 Node.js 版本的 `@scalar/hono-api-reference`。

## 定义任务 API

新建 `src/router.ts`：

```ts
import { os } from '@orpc/server'
import { z } from 'zod'

const TaskSchema = z.object({
  id: z.number().int().positive(),
  title: z.string().min(1),
  completed: z.boolean(),
})

const tasks: z.infer<typeof TaskSchema>[] = [
  { id: 1, title: 'Learn Hono', completed: false },
]

const listTasks = os
  .route({
    method: 'GET',
    path: '/tasks',
    summary: 'List tasks',
    tags: ['tasks'],
  })
  .output(z.array(TaskSchema))
  .handler(async () => tasks)

const createTask = os
  .route({
    method: 'POST',
    path: '/tasks',
    summary: 'Create a task',
    tags: ['tasks'],
    successStatus: 201,
  })
  .input(z.object({ title: z.string().min(1) }))
  .output(TaskSchema)
  .handler(async ({ input }) => {
    const task = {
      id: tasks.length + 1,
      title: input.title,
      completed: false,
    }

    tasks.push(task)
    return task
  })

export const router = {
  task: {
    list: listTasks,
    create: createTask,
  },
}
```

每个 procedure 都由四部分组成：

- `.route()` 定义 HTTP 方法、路径和 OpenAPI 元数据。
- `.input()` 使用 Zod 校验输入，同时向 TypeScript 提供输入类型。
- `.output()` 约束成功响应，防止实现返回不符合契约的数据。
- `.handler()` 编写业务逻辑，`input` 已经完成校验和类型推导。

这里使用内存数组是为了突出 API 结构，重启服务后新增数据会丢失。真实项目应把数据访问放到独立模块中，并连接数据库。

## 挂载到 Hono

将 `src/index.ts` 替换为以下内容：

```ts
import { serve } from '@hono/node-server'
import { OpenAPIHandler } from '@orpc/openapi/fetch'
import { OpenAPIReferencePlugin } from '@orpc/openapi/plugins'
import {
  ZodSmartCoercionPlugin,
  ZodToJsonSchemaConverter,
} from '@orpc/zod'
import { Hono } from 'hono'
import { logger } from 'hono/logger'
import { router } from './router.js'

const app = new Hono()

app.use('*', logger())
app.get('/', (c) => c.json({ message: 'Hello Hono!' }))

const apiHandler = new OpenAPIHandler(router, {
  plugins: [
    new ZodSmartCoercionPlugin(),
    new OpenAPIReferencePlugin({
      docsPath: '/docs',
      specPath: '/openapi.json',
      schemaConverters: [new ZodToJsonSchemaConverter()],
      specGenerateOptions: {
        info: {
          title: 'Task API',
          version: '1.0.0',
        },
        servers: [{ url: '/api' }],
      },
    }),
  ],
})

app.use('/api/*', async (c, next) => {
  const { matched, response } = await apiHandler.handle(c.req.raw, {
    prefix: '/api',
    context: {},
  })

  if (matched) {
    return response
  }

  await next()
})

app.notFound((c) => c.json({ message: 'Not Found' }, 404))

serve({
  fetch: app.fetch,
  port: 3000,
}, (info) => {
  console.log(`Server is running on http://localhost:${info.port}`)
})
```

Hono 和 oRPC 都使用标准 `Request` 和 `Response`，因此 fetch 适配器可以直接处理 `c.req.raw`。`prefix: '/api'` 会移除公共前缀，再让 oRPC 匹配 `/tasks`、`/docs` 和 `/openapi.json`。

`ZodSmartCoercionPlugin` 负责把查询字符串等 HTTP 输入转换成 Zod 需要的类型，`ZodToJsonSchemaConverter` 负责把 Zod schema 转换成 OpenAPI schema。

## 验证 API

启动开发服务器：

```bash
npm run dev
```

读取任务列表：

```bash
curl -i http://localhost:3000/api/tasks
```

创建任务：

```bash
curl -i -X POST http://localhost:3000/api/tasks \
  -H 'content-type: application/json' \
  --data '{"title":"Write documentation"}'
```

把 `title` 改为空字符串会得到 `400 Bad Request`，业务处理器不会收到无效输入。

API 相关页面如下：

- Scalar API Reference：<http://localhost:3000/api/docs>
- OpenAPI JSON：<http://localhost:3000/api/openapi.json>

Scalar 页面会从 CDN 加载前端资源，第一次访问时需要网络连接。OpenAPI JSON 由服务端生成，不依赖浏览器或 Scalar，可以直接提供给代码生成工具、测试工具和其他客户端。

最后运行构建检查：

```bash
npm run build
```

类型检查、实际响应和 OpenAPI 文档都来自同一份 router 定义，这是 oRPC 相比手工维护接口文档的主要价值。
